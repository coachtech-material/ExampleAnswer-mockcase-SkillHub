# マイルストーンマスタ（Certify LMS 開発参画）— 受講生配布版・草案【案②: フェーズ束】

> COACHTECH LMS のタスク管理機能で、運営側が登録するマイルストーンマスタ。
> 各受講生にはこの内容（タイトル + サマリー）がコピーされ、受講生はマイルストーン配下に自分でタスクを起こして進捗を管理する。
>
> - **案②: フェーズ束** — 種別・サブカテゴリでチケットを束ねた 13 マイルストーン構成（対案 = 1 チケット = 1 マイルストーンの案①）
> - 本課題はチケット駆動（全 41 件）。**基本は 1 チケット = 1 タスク** として起票し、規模の大きいチケットは受講生の判断で複数タスク（調査・設計 / 実装 / テスト・動作確認 など）に分割してよい
> - 各チケットの要件・依存関係は要件シート（チケット一覧）を参照。各マイルストーンの「タスク分解のヒント」にあるチケット列挙は **所属の対応表** であり、フェーズ内の着手順は自由（依存チケットのみ先に完了させる）
> - 「★」付きはフェーズ 2: Advance のチケット（フェーズ 1: Basic のチケットをひととおり完了してから着手）
> - 推奨進行: 参画準備（1）→ フェーズ 1: Basic（2〜7）→ フェーズ 2: Advance（8〜12）→ 仕上げ（13）

---

## 1. 参画準備・プロジェクト理解

■ 概要
自リポジトリの生成・環境構築から、既存プロジェクトの全体像把握までを行うマイルストーン。コードはまだ書かない。ここでのコードリーディングが以降すべてのチケットの土台になる。

■ タスク分解のヒント
自リポジトリの生成（Use this template）と環境構築、README の通読、ONBOARDING.md を手がかりにしたコードリーディング（プロジェクト構造・主要ドメインモデル・既存パターンの所在）、3 ロール（受講生・コーチ・管理者）でのログインと主要画面の巡回、テストの実行（環境構築直後は一部が失敗すること、それがバグ修正チケットに対応することの確認）、チケット一覧の通読と進め方の計画。

---

## 2. バグ修正 ①（データ・計算・表示系）

■ 概要
一覧の表示・絞り込み、入力チェック、画面遷移・表示まわりなど、画面で症状を再現しやすいバグを修正するマイルストーン。再現 → 調査 → 修正 → 修正前後の比較というバグ修正の基本サイクルを、既存コードのリーディングと並行して回す。

■ タスク分解のヒント
対象チケットは B-B-02 / B-B-03 / B-B-04 / B-B-05 / B-B-07 / B-B-08 / B-B-10 / B-B-11 / B-B-12 / B-B-13 / B-B-14 の 11 件（サブカテゴリ「データ・計算・表示」の Basic バグ）。各チケットで、再現手順の確認、原因の調査と特定、修正、関連テストの pass 確認、修正前後の比較（証跡）までを 1 タスクの完了条件とする。

---

## 3. バグ修正 ②（認可・認証系）

■ 概要
アクセス制御・認証フローに関するバグを修正するマイルストーン。誰が・どの状態で・何にアクセスできるべきかを既存の認可実装から読み取り、ロールと状態の組み合わせで動作を検証する。

■ タスク分解のヒント
対象チケットは B-B-01 / B-B-06 / B-B-09 / B-B-15 / B-B-16 の 5 件（サブカテゴリ「認可・認証」の Basic バグ）。修正のたびに複数ロール・複数アカウントで動作確認を行い、修正前後の比較を証跡として残す。

---

## 4. 既存機能の拡張

■ 概要
稼働中の機能に管理画面や設定項目を追加する Story のマイルストーン。類似する既存実装のパターン読解 → 踏襲が中心で、参画後に最初に取り組む機能開発として位置づける。

■ タスク分解のヒント
S-B-02 面談パックのマスタ管理 / S-B-03 プランのマスタ管理 / S-B-06 設定・プロフィール の 3 件。各チケットで、類似機能の既存実装調査、仕様案づくりと PM ヒアリング、実装とテスト作成、動作確認、PR 作成。

---

## 5. 新規機能の構築

■ 概要
新しい機能をルーティングからテストまで新規に構築する Story のマイルストーン。画面（Blade）は提供済みのため、バックエンドの実装が対象。

■ タスク分解のヒント
S-B-01 質問掲示板 / S-B-05 個人学習目標の管理 / S-B-07 受講生メモの管理（コーチ） の 3 件。質問掲示板は規模が大きいため、調査・設計とヒアリング / 実装 / テスト・動作確認 のように工程でタスクを分割するのも有効。

---

## 6. 通知基盤と通知機能

■ 概要
アプリ内通知とメール通知の基盤を構築し、その上にお知らせ配信と面談リマインダーを実装するマイルストーン。3 件が依存関係で連なるため、着手順が固定される。

■ タスク分解のヒント
S-B-04 通知基盤（アプリ内＋メール）を最初に完了させ、その後 S-B-08 お知らせ配信（管理者）と S-B-09 面談リマインダー通知（前日・1時間前）に進む。S-B-04 は S-B-01（質問掲示板）の完了が前提。

---

## 7. パフォーマンス改善

■ 概要
既存処理の性能問題を解消する Task のマイルストーン。機能の振る舞いを変えずに内部の処理効率を改善し、改善前後の差を確認する。

■ タスク分解のヒント
T-B-01 コーチダッシュボードの担当受講生一覧のクエリ最適化 / T-B-02 大量レコードを扱う定期実行処理のメモリ最適化（chunk 処理） の 2 件。

---

## 8. ★ 外部サービス連携

■ 概要
Google Calendar・Gemini・Stripe の 3 つの外部サービスを既存機能に統合する Story のマイルストーン。応用フェーズの中核で、各自での API キー取得・環境設定から動作確認までを扱う。

■ タスク分解のヒント
S-A-01 Google Calendar 連携（面談予約） / S-A-02 Gemini AI チャットボット / S-A-03 Stripe 連携（追加面談購入） の 3 件。各チケットで、外部サービス側のセットアップ、既存機能への統合実装、連携失敗時の挙動の設計、README への設定手順追記。S-A-03 は S-B-02（面談パックのマスタ管理）の完了が前提。

---

## 9. ★ 応用機能の拡張

■ 概要
修了証の PDF 出力と、Sanctum 認証を用いた JS フロントからの通知表示を実装する Story のマイルストーン。

■ タスク分解のヒント
S-A-04 修了証 PDF 出力 / S-A-05 Sanctum Cookie 認証 + JS フロント通知表示 の 2 件。S-A-05 は S-B-04（通知基盤）・S-B-08（お知らせ配信）の完了が前提。

---

## 10. ★ バグ修正 ③（並行性・計算ロジック）

■ 概要
二重予約・採点計算・状態の巻き戻しなど、原因特定に深いコードリーディングを要するバグを修正するマイルストーン。

■ タスク分解のヒント
B-A-01 面談予約で同一コーチ・同一時刻枠が二重予約される / B-A-02 模試の採点結果が常に不合格になる / B-A-03 模試をキャンセルしても学習タームが基礎タームに戻らない の 3 件。再現条件の整理と原因の言語化に時間をかけ、調査の足取りを PR の「調査・設計判断」セクションに残す。

---

## 11. ★ リファクタリング

■ 概要
動いているコードの構造を改善する Task のマイルストーン。責務の分離・集約と、外部 API に依存する処理のテスト整備を扱う。機能の振る舞いを変えないことをテストで担保しながら進める。

■ タスク分解のヒント
T-A-02 面談機能のロジックを Action へ分離 / T-A-03 学習進捗の集計ロジックを専用 Service へ集約するリファクタリング / T-A-04 外部 API 連携のモックを使ったテスト追加 の 3 件。T-A-04 は S-A-01・S-A-02・S-A-03（外部サービス連携）の完了が前提。

---

## 12. ★ パフォーマンス最適化

■ 概要
クエリ最適化・キューによる非同期化・キャッシュ導入で応答性能を改善する Task のマイルストーン。

■ タスク分解のヒント
T-A-01 模試マスタ一覧のクエリ最適化 / T-A-05 通知・メール配信の非同期化（キュー） / T-A-06 管理者ダッシュボード集計のキャッシュ化 の 3 件。T-A-05 は S-B-04・S-B-08・S-B-09（通知基盤と通知機能）の完了が前提。

---

## 13. 品質確認・最終提出

■ 概要
提出前の最終チェック。全チケットの PR がマージ済みであることを確認し、テスト全 pass・コード整形・README を仕上げて提出するマイルストーン。

■ タスク分解のヒント
テスト全体の実行と全 pass 確認、コード整形（Pint）の確認、README の最終確認（追加した環境変数・セットアップ手順の記載漏れ）、全 PR のセルフレビュー（5 セクション記述・証跡の添付漏れ）、LMS からの自リポジトリ URL 提出。
